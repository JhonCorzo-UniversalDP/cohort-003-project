     Plan: Lesson Comment Section with Moderation

     Context

     Cadence currently has no discussion or comment features on lesson pages.
     Users have no way to ask questions, share insights, or interact with each
     other within lessons. This plan adds a flat comment section to lesson pages
      where enrolled users can post comments, and instructors (course owners) or
      admins can moderate by deleting any comment. Users can also delete their
     own comments.

     ---
     Step 1: Database Schema

     File: app/db/schema.ts

     Add lessonComments table after videoWatchEvents:

     export const lessonComments = sqliteTable("lesson_comments", {
       id: integer("id").primaryKey({ autoIncrement: true }),
       lessonId: integer("lesson_id").notNull().references(() => lessons.id),
       userId: integer("user_id").notNull().references(() => users.id),
       content: text("content").notNull(),
       createdAt: text("created_at").notNull().$defaultFn(() => new
     Date().toISOString()),
     });

     Then generate migration: pnpm db:generate and apply: pnpm db:migrate.

     ---
     Step 2: Comment Service

     New file: app/services/commentService.ts

     Follows existing pattern (imports db from ~/db, uses Drizzle, exports named
      functions). Four functions:

     - getCommentsForLesson(lessonId) — SELECT with INNER JOIN on users to get
     userName and userAvatarUrl, ordered by createdAt ASC
     - createComment(userId, lessonId, content) — INSERT, returns created row
     - deleteComment(commentId) — DELETE by id, returns deleted row
     - getCommentById(commentId) — SELECT single comment (needed for ownership
     check before delete)

     No authorization logic in the service — that stays in the route.

     ---
     Step 3: Comment Service Tests

     New file: app/services/commentService.test.ts

     Follows ratingService.test.ts pattern: vi.mock("~/db") with getter,
     createTestDb() + seedBaseData() in beforeEach.

     Test cases:
     - Returns empty array for lesson with no comments
     - Returns comments with user info, ordered by createdAt
     - Creates and returns a comment
     - Deletes a comment and returns it
     - Returns undefined for non-existent comment

     ---
     Step 4: Route Loader Changes

     File: app/routes/courses.$slug.lessons.$lessonId.tsx

     In the loader:
     1. Import getCommentsForLesson from ~/services/commentService
     2. Import getUserById from ~/services/userService
     3. Call getCommentsForLesson(lessonId) to fetch comments
     4. If currentUserId, fetch user to get their role
     5. Add to return object: comments, currentUserRole (string | null),
     courseInstructorId (from course.instructorId)

     ---
     Step 5: Route Action Changes

     File: app/routes/courses.$slug.lessons.$lessonId.tsx

     Add two new intents to the existing action function:

     "create-comment":
     1. Validate user is enrolled
     2. Validate content with Zod: z.string().min(1).max(2000)
     3. Call createComment(currentUserId, lessonId, content.trim())
     4. Return { success: true }

     "delete-comment":
     1. Extract commentId from formData
     2. Fetch comment via getCommentById(commentId)
     3. Authorization check — user can delete if:
       - They authored the comment (comment.userId === currentUserId), OR
       - They are admin (user.role === UserRole.Admin), OR
       - They are the course instructor (currentUserId === course.instructorId)
     4. If unauthorized, throw 403
     5. Call deleteComment(commentId)
     6. Return { success: true }

     ---
     Step 6: CommentSection UI Component

     New file: app/components/comment-section.tsx

     Props: comments, currentUserId, currentUserRole, courseInstructorId,
     enrolled

     Structure:
     - Header: "Comments (N)"
     - Create form (only shown to enrolled, logged-in users): Textarea + Button,
      uses useFetcher to avoid full page navigation. Clear textarea on
     successful submit via useEffect.
     - Comment list: Each comment shows:
       - UserAvatar (reuse existing ~/components/user-avatar)
       - User name + relative timestamp
       - Comment content
       - Delete button (if authorized) — each uses its own fetcher form
     - Empty state: "No comments yet. Be the first to comment!"

     Delete permission per comment: currentUserId === comment.userId || 
     currentUserRole === "admin" || currentUserId === courseInstructorId

     Reuses: Button from ~/components/ui/button, Textarea from
     ~/components/ui/textarea, UserAvatar from ~/components/user-avatar

     ---
     Step 7: Wire Into Lesson Page

     File: app/routes/courses.$slug.lessons.$lessonId.tsx

     1. Import CommentSection from ~/components/comment-section
     2. Destructure new loader fields (comments, currentUserRole,
     courseInstructorId)
     3. Render <CommentSection> after the mark-complete/up-next block (~line
     593) and before the prev/next navigation (~line 595)
     4. Only render for enrolled users
